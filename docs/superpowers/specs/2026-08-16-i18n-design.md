# i18n Design: Chinese (zh-CN) + English (en)

## Overview

Add internationalization (i18n) to daedalOS using a lightweight, zero-dependency
React Context approach. Supports UI string translation and date/time/number
localization. Language preference persists via localStorage.

## Architecture

### LanguageContext (`contexts/language/`)

- `index.tsx` — Provider + `useLanguage` hook
- Exposes `{ locale: Locale; setLocale: (locale: Locale) => void; t: (key: string, params?: Record<string, string | number>) => string }`
- `Locale` type: `"en" | "zh-CN"`
- On mount: read from `localStorage` key `"language"`, fall back to `DEFAULT_LOCALE` (`"en"`)
- On `setLocale`: persist to `localStorage`, update `document.documentElement.lang`
- `t()` performs flat-key lookup in the active locale dictionary; falls back to English if key missing; falls back to the key itself if missing from both

### Translation Dictionaries (`locales/`)

- `en.json` — English (source of truth)
- `zh-CN.json` — Chinese translation
- Flat key structure, dot-separated namespaces:
  ```json
  {
    "menu.file.open": "Open",
    "menu.file.openWith": "Open with",
    "menu.file.cut": "Cut",
    "taskbar.start": "Start",
    "dialog.run.title": "Run"
  }
  ```
- Dictionaries imported statically (no lazy loading — small enough for bundle)

### Date/Time/Number Localization

- Replace all `DEFAULT_LOCALE` usages in `Intl.DateTimeFormat` / `toLocaleString` / `Intl.NumberFormat` with the dynamic locale from context
- Affected files:
  - `utils/functions.ts` — `formatTimeStamp` and similar
  - `components/system/Taskbar/Clock/functions.ts` — clock formatters
  - `components/system/Dialogs/Properties/GeneralTab.tsx` — file properties dates
  - `components/system/Files/FileEntry/functions.ts` — file entry date formatting
  - `components/apps/Terminal/useCommandInterpreter.ts` — `ls` time format
- Pattern: LanguageProvider maintains a module-level currentLocale variable (in contexts/language/index.tsx) that mirrors the context state. Utility functions that cannot access React context import a getLocale() getter that returns this variable. This avoids threading locale through every function call signature while keeping a single source of truth.

### Language Switcher UI

- Add a language toggle in the Start Menu sidebar or Taskbar context menu
- Simple toggle: English ↔ 中文 (since only 2 languages)
- Uses `setLocale` from `useLanguage()`

### HTML lang attribute

- `pages/_document.tsx` currently sets `<Html lang={DEFAULT_LOCALE}>` (static)
- LanguageProvider updates `document.documentElement.lang` on mount and on locale change

## Implementation Scope

### Phase 1: Core Infrastructure
1. Create `contexts/language/` (index.tsx, types)
2. Create `locales/en.json` and `locales/zh-CN.json` with initial key set
3. Wrap app with LanguageProvider in `pages/_app.tsx`
4. Create `useLanguage` hook

### Phase 2: String Migration
5. Extract hardcoded UI strings from high-traffic components into translation keys
6. Replace string literals with `t("key")` calls
7. Priority files (by user-facing impact):
   - `components/system/Files/FileManager/useFolderContextMenu.ts` — context menu items
   - `components/system/Taskbar/` — taskbar labels
   - `components/system/StartMenu/` — start menu entries
   - `components/system/Dialogs/` — dialog titles and buttons
   - `components/apps/Terminal/useCommandInterpreter.ts` — terminal command descriptions

### Phase 3: Date/Time Localization
8. Update `Intl.DateTimeFormat` calls to use dynamic locale
9. Update `toLocaleString` calls to use dynamic locale

### Phase 4: Language Switcher
10. Add language toggle UI in Start Menu sidebar
11. Wire to `setLocale`

## Key Decisions

- **Flat JSON keys** (not nested objects) — simpler lookup, easier to diff
- **Static import** of dictionaries (no lazy loading) — total size small, avoids async complexity
- **Fallback chain**: active locale → English → raw key
- **No ICU message format** — simple `{{param}}` interpolation is sufficient
- **localStorage persistence** — consistent with existing session mechanism
- **Module-level locale variable** for non-React utility functions that can't access context (e.g. `Clock/functions.ts` formatters), set by LanguageProvider on mount/change

## Non-Goals

- Lazy loading of locale files
- Pluralization rules (not needed for 2 languages at current scale)
- RTL support
- Server-side rendering of translations (static export)
